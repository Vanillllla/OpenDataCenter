Тесты ядра проверяют не только отдельные формулы, но и реальный `ComputeEngine.plan`, используемый `ClusterScheduler`: ограничения полосы/энергии, отсутствие награды без вычислений, распределение остатка, разные профили задач, недопустимость суммирования слабых VRAM для AI, отключение WAN/LAN, поведение при добавлении коммутатора. ## Ручной чек-лист первого запуска

### Сборка и запуск
- [ ] Установить JDK 8; `java -version` и `javac -version` соответствуют 1.8.
- [ ] `test-core.bat` завершился PASS.
- [ ] `build.bat` завершился BUILD SUCCESSFUL, создан reobfuscated JAR.
- [ ] `runClient` либо установленный JAR запускается без ошибок; FML видит odc 0.2.0-alpha.
- [ ] В `latest.log` нет missing model/texture/recipe для odc.
- [ ] Создать новый творческий мир; предметы отображаются во вкладке Redstone, оба языка работают.
- [ ] При возможности запустить dedicated server с тем же JAR и подключиться клиентом; проверить отсутствие загрузки client-only классов на сервере.

### Серверы и блоки
- [ ] Собрать 1U с одним GPU, 2U с двумя, 4U с четырьмя; CPU обязателен. Попробовать слишком много GPU, пустой CPU, заполненный output — сборка отклоняется без потери компонентов.
- [ ] Вставить 4×1U, 2×2U, 1×4U, смешанные 1U+2U+1U; недопустимые пересечения отклоняются.
- [ ] Shift-click в обе стороны; закрытие GUI, извлечение и разрушение стойки не дублируют/не теряют компоненты.
- [ ] Проверить поворот на четыре стороны, открытая/стеклянная стойка, две стойки друг над другом, пустой bay, CPU/GPU-панели.
- [ ] Активный сервер: зелёный LED; неактивный и пустой: нет зелёной активности; второй LED мягко мигает. Проверить независимую работу нескольких серверов в одной стойке.
- [ ] Проверить внешний вид антенны, коммутатора, ПК, кабельных ответвлений во всех шести направлениях, декоративных панелей.

### Три задачи и сеть
- [ ] Подключить PC, rack, switch, station через Data Cable и всех четырёх — через Power Cable к творческой батарее.
- [ ] Привязать стойку к контроллеру, назначить 1U A на mining, B CPU-only на bank, C GPU T2 на AI. Запустить все задачи из DataOS.
- [ ] WAN=128, LAN=64, used<=64, суммарная потребность 84 Mb/s. Есть сетевое ограничение. На стабильном полном питании отдельные показатели примерно 3/4, 12/16, 49/64 Mb/s.
- [ ] Добавить второй powered switch — LAN=128, задачи работают 4/4, 16/16, 64/64 Mb/s. Увеличивать WAN потребуется после исчерпания 128 Mb/s.
- [ ] Назначить сервер без GPU на mining — несовместим; GPU T1 (4 GB) на AI — несовместим; CPU-only на bank — работает. GPU не обязателен для bank.
- [ ] Остановить только одну задачу, две другие продолжают работу; соответствующие LED гаснут в течение расчётного цикла.
- [ ] Привязать несколько серверов к одной задаче — производительность складывается. Один сервер не начисляет одновременно две выплаты.
- [ ] Добавить второй компьютер того же игрока и назначить другую стойку на него — общая сеть не удваивается. Сделать кольцо data cable: устройства не учитываются дважды.
- [ ] Разорвать путь к стойке — доход останавливается после цикла; восстановить — возобновляется. Проверить альтернативный маршрут через кабельную петлю.
- [ ] Убрать единственную станцию: WAN=0, работа остановлена. Убрать единственный коммутатор: LAN=0 или путь разорван, работа остановлена.
- [ ] Убрать питание коммутатора/станции/PC и дождаться разряда буфера; соответствующие устройства выключаются. Убрать питание стойки, дождаться разряда; доход прекращается.
- [ ] Снизить `creativeBatteryOutput`, проверить троттлинг и отсутствие дохода при исчерпании энергии. Проверить отсутствие работы в выгруженном чанке и возобновление после загрузки.

## Известные ограничения

Нельзя гарантировать, что первый Forge build или запуск пройдёт без исправлений: в текущей среде отсутствуют необходимые зависимости. ASIC, охлаждение, установка ОС, графический редактор конфигурации, сетевые порты/маршрутизация и сторонние интеграции не входят в этот релиз. LED используют анимированные текстуры, не fullbright/emissive рендеринг. Моделирование сети — агрегированная общая шина. Числа баланса предварительные.
