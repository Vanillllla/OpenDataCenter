# OpenDataCenter 0.4.0-alpha — отчёт о проверке

## Подтверждено в среде подготовки

- Чистый Java `TaskEngineTest`: 15 000 случайных сценариев, 1 112 611 проверок, включая целевые случаи нескольких задач на одном сервере, откат строгой задачи, отдельные физические GPU, VRAM, ручные лимиты, приоритет, группы, резервирование диска, CPU/GPU нагрузку, WAN, локальные switch, ограничения PSU.
- Чистый Java `EconomyEngineTest`: 25 000 случайных операций, 150 009 проверок, включая сохранение суммы при переводе, отсутствие отрицательных балансов, курс, сложность и целевой прогресс AI.
- Регрессионные тесты прежней аппаратной/сетевой/геометрической математики: 1 613 018 + 261 776 + 119 184 проверок (не являются игровыми тестами 0.4.0).
- `tools/validate_assets.py`: 17 978 проверок ресурсов, 276 моделей, 384 состояния кабелей/реле.
- 471 файл `src/main/resources/assets/` побайтно совпадает с архивом 0.3.2. `RackRenderer.java` и `PatchCordMesh.java` также не менялись.
- JDK compiler API разобрал синтаксис 29 Java-файлов с целевым уровнем Java 8. Проверка зависимостей/типов Forge этим не выполняется.

## Не подтверждено

JDK 8 отсутствует, установлен JDK 21; `maven.minecraftforge.net` не разрешается из среды. Поэтому полной Forge-компиляции, reobf, запуска клиента/выделенного сервера, FPS/TPS, NBT round-trip в реальном Forge и GUI packet integration не проверено. Готовый JAR не предоставляется. Необходимо тестировать в новом мире.

## Проверки игрового уровня (ещё не выполнены)

1. Собрать `gradlew.bat build`, запустить новый творческий мир и отдельный выделенный сервер. Проверить, что клиентские классы не загружаются на dedicated server.
2. Поставить открытые/стеклянные стойки 4U/9U всех четырёх ориентаций. ПКМ по каждому юниту, серверы 1U/2U/4U, пересечение центральной границы, два switch (второй отклоняется), Ctrl+ПКМ в обоих режимах игры, полный инвентарь, извлечение пересекающегося модуля. Проверить отсутствие дюпа.
3. Графический switch: занятые/свободные порты, расход/возврат кабеля, отсутствие NIC, разрыв/снятие коммутатора. Проверить неизменный рендер 3D патч-кордов.
4. Собрать CPU-only и GPU-узлы. Создать NTC/CRX/VRX, Bank, AI training/inference. Авто и ручные лимиты CPU, GPU, RAM, диск, сеть. Несколько задач на сервере, исключительность GPU, нехватка VRAM, строгий откат, гибкая работа. Проверить выбранные группы и массовое управление. Переименовать сервер и задачу.
5. Перегрузить PSU, проверить аварийное отключение и ручной старт. Отключить силовое реле; серверы не должны автоматически стартовать после снятия сигнала. Проверить, что выключенный сервер не расходует FE, а коммутатор продолжает расходовать FE.
6. Проверить доход после фактической работы, отсутствие дохода без питания/сети, сложность через 60 секунд, CRX/VRX→NTC, личный/корпоративный перевод, покупку товара при полном инвентаре, единственную выплату AI после завершения. Сохранение и восстановление после перезапуска мира.
7. Два терминала одной сети: одинаковые задачи, отсутствие двойной выплаты; слияние двух сетей и разделение. Другой игрок без прав не может управлять или забрать серверы. Никаких обращений к настоящему интернету.
8. Полностью выгрузить все устройства, кабели и батареи одной изолированной сети; подождать на работающем сервере, вернуться, сравнить баланс. Проверить частичную загрузку (возможна пауза, но не двойная выплата), отключение батареи/изменение реле, перезагрузку мира и отсутствие дохода за время выключения. Не считать механизм проверенным, пока эти сценарии не пройдут.
9. Проверить GUI на GUI Scale 1/2/3/Auto, кнопки, ввод русского имени, навигацию, длинные строки, корректность обновлений при нескольких игроках.
10. Проверить TPS на десятках и сотнях стоек, особенно после изменения кабеля/загрузки чанков. Не было фактического замера производительности.
