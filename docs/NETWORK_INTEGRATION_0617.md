# Network Integration 0.6.1.7

## Расчёт и допуск

`PhysicalNetwork.bandwidth` — единый расчёт по измерению мира с общими лимитами антенн и всех логических связей. `NetworkAdmission` формирует запросы по фиксированным назначениям каждой активной задачи; пробная заявка не может лишить действующие задачи принятой полосы. `ClusterScheduler` и виртуальный планировщик допускают обслуживание только при обеспечении всех запрошенных серверных резервов. При изменении маршрута CPU/GPU/RAM/накопители не переносятся. Нагрузка расчётная, а не измеренные пакеты. Все текущие контракты используют WAN; LAN API сохранён для будущих задач.

`BandwidthEngine.additional` рассчитывает дополнительную WAN-полосу по остаточному графу, сохраняя существующие маршруты. Значения отдельных серверов не складываются: их маршруты могут пересекаться. Общий WAN в мониторинге измеряется на входах терминалов; остаток до серверов указан отдельно. Физический номинал NIC не является гарантией доступной полосы. Старый прямой WAN не используется игровым планировщиком.

## Выгрузка чанков

Снимок виртуального дата-центра допускается к расчёту при подтверждённой эксклюзивной физической топологии и независимом питании, если вся сохранённая область выгружена. Он входит в тот же глобальный граф по тем же UUID. При частичной загрузке либо неподтверждённой или разделяемой сети виртуальная полоса не выдаётся. Это консервативный режим, не полноценная симуляция общих антенн через границы выгрузки. Начисления вне запущенного мира не добавлены.
