# DataOS Event System — 0.5.4.2

`EventJournal` — независимая Java-модель, `EventSystem` — NBT/Forge и представление для DataOS. Время — счётчик секунд планировщика TaskData, а не часы ПК; при закрытом мире он не движется. События имеют уникальный UUID, первоначальный и последний момент, последовательность для сортировки, категорию, уровень, код, описание, владельца, якорь, первоначальный якорь, тип и UUID источника, число повторов, валюту и сумму в тысячных долях монеты при наличии. Регистрация происходит в серверных операциях и при смене состояния.

Лимит `dataos.journalLimit`: 256 по умолчанию, 16–4096. Каждая запись хранится один раз. Видимость журнала определяется текущими стойками/контроллерами в сети и владельцем. После подтверждённого объединения сетей обрезается объединённая история, при разделении запись остаётся с исходным якорем. При демонтаже стойки/контроллера история переносится на найденный оставшийся якорь без изменения исходного UUID; если найти его не удалось, записи остаются со старым якорем. Полностью удалённые изолированные якоря не видны из другой сети. Частичная выгрузка чанков может временно скрывать события; обнаружение разделения не основывается лишь на исчезновении устройства и пропускает неоднозначные переходы через незагруженные чанки. Сетевой движок не переписан. Старые 64 текстовые записи не мигрируются (alpha, новый мир).

Предупреждения и ошибки с одинаковыми параметрами объединяются в течение 60 секунд от предыдущего появления; выплаты — в пределах фиксированной 60-секундной корзины по источнику и валюте. Финансовые записи содержат реально зачисленные средства, отдельно удержание в погашение долга и списанные штрафы. Журнал не меняет экономические формулы. Текст серверных событий пока английский, основные управляющие элементы GUI имеют русский/английский варианты.

`TaskData.recentEvents(tile,count)`, `errorCount(tile)`, `financialEvents(tile)` — методы чтения для следующего этапа. GUI получает серверно отфильтрованные окна до 32 строк; отдельная карточка запрашивается по UUID. Переход к отсутствующему или завершённому объекту блокируется.

Проверено: автономные наборы `tools/test-core.sh` (в том числе 105957 проверок журнала: лимит, изоляция, сортировка, агрегация, восстановление модели, перенос истории); Java-синтаксис; типы DataOSScreen с локальными заглушками API. Добавлена Gradle-проверка `verifyEventPersistence` с реальными NBT-классами Forge, но она не запускалась в этой среде: нет JDK 8 и подготовленных Forge-зависимостей. Не подтверждены реальный NBT round-trip, сетевые пакеты, визуал и игровые сценарии (в частности частичные выгрузки/объединения). Это архив исходников, не JAR.
