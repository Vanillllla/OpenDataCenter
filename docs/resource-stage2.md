# Resource Manager 0.5.3 — архитектура

Реальный путь симуляции: ClusterScheduler / OfflineState → TaskData.plan → AllocationCache → FixedResources.plan. Старая TaskEngine.plan сохранена как автономная контрольная реализация для регрессионных тестов, не используется для исполнения игровых задач. Пулы scoped по текущей физической сети и владельцу, имена регистрозависимы; Default используется по умолчанию.

Редактор `TaskConsole` держит временный черновик, не расходующий ресурсы. При выборе одинаковой модели `Ledger.adjust` предпочитает уже выбранные машины, затем машины с большим свободным объёмом данной модели. Пользователь раскрывает модель и переопределяет любой физический экземпляр. Физические строки запрашиваются окнами по 128 записей при вертикальной прокрутке. Никаких стрелок перелистывания. Сервер повторно проверяет авторизацию, ревизию окна, принадлежность пулу, актуальную топологию, ограничения контракта и резервы перед атомарным применением.

Хранение: UUID сервера + тип + аппаратный слот + номер ядра/чипа + индекс модели. Для RAM и накопителей резервируются GB, для сети целые Mbit/s. Для дисков независимо резервируется необходимая полоса MB/s в момент запуска (по выбранным накопителям, сначала более быстрым); при паузе освобождается I/O, сохраняются GB. Вся единица работы размещается локально; требуемые CPU, GPU, VRAM, RAM, диски и сеть должны находиться на одном сервере. Избыточные выбранные ресурсы тоже резервируются. Коэффициенты существующих задач сохраняются; для неоднородных дисков коэффициент скорости взвешен по выбранному объёму. Score и выплаты рассчитываются по существующему каталогу Workload и коэффициентам ContractMarket. Временные резервы не перераспределяются между задачами. При потере любой зафиксированной части задача не получает работу до восстановления назначений или разрешённой ручной перенастройки; периодические услуги используют существующие штрафы и техработы.

Уже записанные дисковые данные нельзя уменьшить или перенести в редакторе после начала исполнения. Миграция данных не реализована; отмена задачи освобождает данные. Fixed-контракты сохраняют точный набор и I/O, Pinned-контракты — множество серверов, Single-контракты — один сервер. Майнинг меняет конфигурацию после паузы; услуги — после техработ, нефиксированные конечные контракты могут менять ресурсы на ходу. Ресурсы активных задач и сохранённые данные учитываются даже на физическом сервере, отделившемся от контроллера. Виртуальная симуляция по-прежнему работает только с проверенными полностью выгруженными снимками.

Ограничения: идентичная деталь, заменённая на ту же модель в том же слоте, неотличима (нет серийных номеров). Сеть представлена эффективным интерфейсом сервера, а не несколькими индивидуальными NIC. Новый ключ WorldSavedData, старые миры не мигрируются. Java 8-синтаксис и автономные тесты проверены на JDK 21; полная сборка Forge 1.12.2 и GUI/NBT в Minecraft не проверены.
