# 0.6.1.1 — Physical Network Foundation

База: архив 0.5.4.3-alpha. Этот этап не реализует маршрутизацию трафика, новую систему резервов или графический редактор.

## Архитектура

`PhysicalTopology` — автономная модель. LAN-компонента состоит из соседних Data Cable, стоек (включая обе половины), управляющих терминалов DataOS и сетевых терминалов. Прямое соседство совместимых LAN-блоков сохраняется, как в предыдущих версиях. Оптические компоненты состоят только из блоков Fiber Cable: терминал и антенна являются оконечными устройствами, не транзитными узлами. Для каждой LAN-карты обнаруживаются все терминалы и все антенны, соединённые с ними оптическими сегментами. Одна антенна может отображаться в нескольких LAN-картах с одинаковым UUID, но не соединяет их. При объединении LAN антенна не дублируется в списке, связи с каждым терминалом сохраняются.

В стойке обнаруживается установленный коммутатор, а сервер только при наличии существующего патч-порта и NIC. Пустые стойки существуют в физическом графе, но не отображаются устройствами. Uplink terminal–switch не создаётся автоматически. Типы RADIO, SATELLITE, TOWER, TERMINAL, SWITCH, SERVER предусмотрены моделью; блок вышки и финальные антенны — этап 2.

`PhysicalNetwork.view(World, BlockPos)` — серверный API для будущего терминала. Возвращает домен, список устройств по UUID, автоматические FIBER/PATCH-связи, признак полной загрузки LAN, позиции с подтверждённой связностью от точки запроса и неоднозначные UUID. Состояние устройства содержит номинал Mbps, последнюю расчётную нагрузку для старых серверов/коммутаторов и признаки доступности. `usedMbps=-1` означает неизвестную нагрузку (антенны и новые терминалы до этапа 4 либо выгруженные устройства), не ноль. `available` означает локально подтверждённое питание/наличие, а не наличие маршрута в WAN; `Link.verified` означает физически проверенный путь, не гарантированную скорость. Для неполной LAN нельзя считать весь домен доступным. Модель хранит измерение и координаты, слот/порт сервера и UUID родительского коммутатора. UUID серверов сохраняются в существующем NBT корпуса; UUID коммутаторов — в NBT предмета, антенн/терминалов — в TileEntity. Дубликаты UUID внутри карты не выдаются за независимые устройства. Creative-копии коммутаторов получают новый UUID при вставке.

## Хранение и обновление

Индекс `odc_physical_network_v1_<dimension>` хранится в WorldSavedData. При перезапуске известные записи сохраняются, но ни один путь не верифицирован до загрузки соответствующих чанков. Установка/удаление кабелей обновляет индекс, изменения TileEntity и инвентаря ставят позицию в очередь. При загрузке чанка проверяются его известные позиции и релевантные блоки в непустых секциях; соседние чанки принудительно не загружаются. При выгрузке записи сохраняются, а подтверждение доступности снимается. Каждые 20 тиков освежаются характеристики загруженного оборудования. Изменение только нагрузки или метаданных не перестраивает кэш кабельных компонент. Реальный NBT и событийные сценарии Forge требуют проверки в игре. Нет миграции старых сохранений; рекомендуется новый мир.

## Переходный режим

Сетевой терминал T1 (1000 Мбит/с) и оптоволокно — временные творческие блоки с простыми моделями; ПКМ по терминалу выдаёт информационную сводку. Рецепты и финальные модели добавляются позже. Номиналы существующих станций (128/512 Мбит/с) и коммутаторов не изменены. `Network` и `ClusterScheduler` сохраняют старый механизм расчёта задач до этапа 7; станция больше не является транзитным LAN-узлом, напрямую прилегающие старые станции учитываются как переходные оконечные источники только для одной загруженной LAN. В новой карте Data Cable не подключается к антеннам, только оптоволокно. Оптическая сеть **ещё не предоставляет полосу задачам**. Полноценное единое распределение общего источника и новых маршрутов — этапы 4/7. Не использовать промежуточную версию для проверки финальной пропускной способности или виртуального WAN.

## Проверки

`bash tools/test-core.sh` — пройдены автономные тесты, в том числе 9806 новых проверок: пустые стойки, коммутатор/сервер, общий источник двух LAN, объединение и разрыв, восстановление, отсутствие транзита через оптические оконечные устройства, сохранённый индекс без подтверждения, дубли UUID и 2000 случайных изменений линии. `python tools/validate_assets.py` — 23788 структурных проверок. Добавлен `verifyPhysicalNetworkPersistence` для запуска с настоящими NBT-классами при сборке Forge; здесь не выполнен (нет JDK 8 и Forge). Сборка и игра не проверены.
